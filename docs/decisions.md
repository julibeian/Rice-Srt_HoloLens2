# 关键技术决策

按设计问题保留路线变化，便于成员理解现有实现。每项决策关联理由、影响和后续验证。

## D-001：眼镜独立采集，云端完成识别

原型通过 PC 转运图片验证了采集与结果回传。当前应用改为眼镜直接上传，减少正常使用对 PC 的依赖。PC 通道继续用于部署、诊断和实验控制；模型服务沿用现有后端。网络可用性与恢复需要独立实验。

## D-002：使用应用内 PV 预览与区域控制

系统相机交接曾出现空文件或无法闭合的返回流程。应用内预览让取景区域、对焦、曝光、质量检查和裁剪保持在同一流程。驱动不支持曝光锁定时不请求该能力，旧 Canvas 缺少 `toBlob` 时采用 JPEG 编码回退。

取景框由使用者指定；自动叶片分割作为后续研究。区域控制调用成功后，仍需用真实叶片和多光照结果检查成像效果。

## D-003：原图、裁剪与结果建立可核查关联

原图用于检查成像和裁剪范围，裁剪图用于识别。上传、返回和历史使用同一请求身份与图像 SHA256，避免错图、迟到响应和重传结果串用。取消、模糊或持续过曝不能转而上传旧图。

## D-004：将安装、运行和可见操作分开验收

URI 激活可能复用旧进程，系统接受请求也不保证出现新窗口。构建使用带版本入口页和内容哈希脚本名，诊断读取实际运行会话。全息取景框移动和快门事件等可见结果单独记录。

## D-005：控制使用官方接口，并有独立恢复保护

原生输入、独立窗口和模拟 API 的成功返回不足以证明界面可用。实验工具使用匹配的 x86 Perception Simulation 组件及认证门户画面；具名租约在设备端计时，控制中断也能恢复默认模式。

门户叶证书只有在既有 SSH 身份、公钥、签发者、目标名称与有效期连续性通过时才更新，不通过关闭 TLS 验证来处理续签。

## D-006：固定构建输入，实验原件独立管理

共用界面文件随仓库固定，成员可以独立构建。第三方来源与文件摘要保留在输入清单中。团队仓库发布版本结论、实验协议和资源索引；原始运行日志与环境配置由执行环境保存，实验报告通过编号和摘要引用。
