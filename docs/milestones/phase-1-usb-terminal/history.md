# 第一阶段重要迭代历史

范围：电脑通过 USB 管理同一台 HoloLens 2。日期按 Asia/Shanghai 记录，先后出现的成功和失败均保留其范围。实时画面与鼠标控制的历史属于 [第二阶段](../README.md)。

| 日期 | 问题或变化 | 形成的做法与结果 |
| --- | --- | --- |
| 2026-10-21 | 建立最初的 USB NCM + Windows SDK SSH 管理通道 | 一次开发配对后，后续新进程复用配对；远端只读命令和文件往返哈希通过。明确设备没有常规 CMD/PowerShell，开发用户无管理员或 SYSTEM 权限。 |
| 2026-10-21 | 前台终端退出、工作进程或监督进程终止后，需要恢复 | 改为 Windows 任务计划程序管理监督进程，再由监督器启动桥。前台 `exit` 不停止后台；当前用户登录与周期任务负责重新拉起。最初未验证重启或实际拔插。 |
| 2026-10-23 | USB 重新接入后，发现 GUID 改变，旧条件把原设备排除 | 改为名称发现候选、旧 GUID 仅作优先提示，最后固定核对原 SSH 指纹；错误指纹拒绝连接，不自动重配对。 |
| 2026-10-24 | USB 与网络管理可达性随时段变化；低功耗时可能无法执行管理命令 | 保存各次离线、重连与低功耗观察；不把早先空列表写成持续离线，也不把一次连接成功写成永久在线。Wi-Fi、云服务与电脑管理链路分别验收，临时 IPv6 探针未成为自动备用链路。 |
| 2026-10-25 | SDK 发现可能无期限等待 | 单次发现设 12 秒上限，超时只结束本次创建的 SDK 子进程；不会因此结束其他 SDK 程序。 |
| 2026-10-25 | 失联后对象未完整释放，发现成功后又建立第二次 SSH 连接 | 断开异常仍释放对象；桥直接接管已经通过原指纹认证的发现会话。历史连续两次重连约 4.4 秒，恢复后均执行实际设备命令。 |
| 2026-10-25 | 桥进程存在但 SDK 调用卡住，原监督方式无法发现 | 增加 `UpdatedAt` 和 `ActiveOperation`，按进度超时恢复自己的桥。冻结桥的历史故障注入约 131 秒恢复；未知命令结果不重放。 |
| 2026-10-25 | Windows 读锁导致状态文件替换失败；任务排队时过早报启动失败 | 状态文件替换加入限时重试；任务启动以实际管道响应确认。真实文件共享冲突和启动过渡均有回归检查。 |
| 2026-10-25 | 接电短时待机与网络手动连接影响无人值守调试 | 对原设备先备份，再调整已有网络的自动连接及接电待机值，保留电池原值。只发送一次实际重启，约 68 秒后原 SSH 身份和命令恢复；连续约 200 秒、14 个状态样本保持。此配置是该设备的历史条件，不作为其他设备默认设置。 |
| 2026-10-25 | 原说明依赖开发电脑已有工具、配对和路径 | 增加新电脑完整步骤、占位配置解释、观察身份与可信身份的区别、只读环境检查，以及独立阶段分支。新文档不声称第二台电脑已经完成真机复现。 |
| 2026-10-31 | 每次重连都先做完整 SDK 发现，约 4–5 秒；桥停止后重启更慢 | 首次 SSH 指纹通过后缓存已验证 USB 端点，后续重连先探测该端点并直接认证，命中约 0.9 秒；缓存只在设备名与指纹仍匹配 `config.json`、且本次 SSH 指纹再次通过时使用。缓存失败时完整发现限流为每 10 秒一次；桥改为直接拉起并由监督器按 PID 接管，冷启动约 3.5 秒。`ConnectionMethod`、`LastConnectMs` 记录实际路径与耗时；新增 `tests/HoloLens.FastConnect.Tests.ps1`。 |

原始验收材料留在受控实验资料中。本分支发布从记录整理的结论和可执行源码；[验证说明](validation.md) 标明哪些是历史真机证据、哪些是本次离线检查。
