# 屏幕采集取消竞态修复

2026-10-30，Asia/Shanghai。独立验证包更新为 **1.0.0.2**；桌面产品仍为 **0.3.3.0**。本轮修复采集验证组件，没有取得新的眼镜帧率证据，25 fps 等原目标保持。

## 已复现的问题

旧组件在选择器返回 Completed 时先读取结果，随后才检查停止标志。真实工作函数配合模拟异步操作的本机检查显示：停止已请求，`GetResults` 仍被调用一次；若返回有效来源，原路径还会继续初始化采集。该检查没有打开系统选择器或实际屏幕采集，旧源码、测试程序及失败结果单独保留。

另一个缺陷是取消请求返回后立即关闭操作，未确认其已进入终态。微软的 [IAsyncInfo.Close 约束](https://learn.microsoft.com/en-us/uwp/api/windows.foundation.iasyncinfo.close)要求异步操作完成后才能关闭，不能将发送 Cancel 当作终态确认。

## 本轮改动

- 在读取选择结果及各个采集初始化步骤前重新检查停止请求；读取结果期间收到停止时，不再继续读取来源尺寸或初始化采集。
- 每次操作只发送一次取消。请求返回后，最多再观察约两秒确认终态；仍在运行或状态不明时跳过 Close，保存未确认结果。该预算不保证中断阻塞的系统调用，真实设备行为仍待验证。
- 保存取消、关闭 HRESULT 和终态／释放确认。结果不明时阻止再次选择；能力检查也不将该失败重置为 ready。新测试须先确认该验证进程已经结束，再启动新进程。
- 组件协议升级为 2，前端拒绝旧组件，避免宿主缓存旧 DLL 时绕过新逻辑。无有效帧或释放结果未确认时，不将任务结束计为测量通过。

## 本机验证

同源 x64 DLL 实际加载的 28 个 ABI 断言通过。真实原生工作函数的九类模拟异步场景全部通过：停止先于完成、取消获确认、取消被拒绝、取消未获确认、用户取消、异步错误、读取结果时停止、关闭失败、取消与完成交错。

取消未获确认的样本约两秒结束观察，未调用待完成操作的 Close；取消被拒绝的样本同样没有调用 Close。两者均保存未知状态。取消／关闭失败后的 Inspect 保留失败，不重置状态。这些场景没有打开选择器、创建真实采集会话或发送设备输入。

前端与计数共 **16 项检查通过**，包括重复时间戳、失败释放、旧组件协议和空帧结果。ARM64 编译以警告视为错误通过，Appx 清单验证通过；原生测试和最终包逐项绑定同一源码哈希。PowerShell 语法检查通过。
