# 最新方案（2026-10-29）

一句话：**保持连接，不让它睡；睡了就分级叫醒。**

## 现在的做法

1. **连接**：USB 接入后核对设备身份，建立管理通道；断线自动重连，后台看护。
2. **画面与操作**：电脑端实时画面，点按直接作用到眼镜；应用可以启停。
3. **不让它睡**：连接期间维持设备正常功耗，桥和租约持续运行。
4. **分级唤醒**：
   - 深度睡眠、完全失联：发一次设备发现请求，约 16 秒恢复；
   - 还能连上、但没有画面：受控重启，约 5 分钟恢复；
   - 无论哪种方式，恢复后必须解出新画面才算成功。
5. **自动看护**：每 3 分钟检查一次；不可达或低功耗时按上面的顺序处理；重启有 15 分钟冷却，避免反复重启。

## 为什么这样做

- 睡眠时网页管理接口会失效，不能指望它来唤醒；
- 设备发现请求能唤起深度睡眠，成本最低，优先使用；
- "还能连上但没有画面"的状态只有重启可靠，所以放在最后并限流。

## 现在还没做到

- 画面约 21 帧，目标 25 帧；
- 125% 缩放下的真机点按、三维交互、长时运行尚未验收；
- 静态/动态识别模型、前后端尚未开始。
