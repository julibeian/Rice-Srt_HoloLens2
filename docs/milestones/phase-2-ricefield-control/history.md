# 第二阶段重要迭代历史

第二阶段处理真实画面与输入，不把第一阶段的 USB SSH 管理连通作为控制成功证据。

| 日期 | 路线或问题 | 结果与保留限制 |
| --- | --- | --- |
| 2026-10-23 | 原生输入接口、模拟位姿及窗口启动可返回成功，却不能证明用户实际看到或点按 | 确立接口、真实画面、具体控件结果分别验收。MRC 照片未显示某窗口也不足以证明窗口不存在。 |
| 2026-10-23 | 旧独立面板组件存在 x64 EXE 与 x86 依赖混合，出现启动错误 | 用匹配的 legacy x86 SDK 构建输入编码器，并做离线输入包检查；不把离线成功当真机操作成功。 |
| 2026-10-23 | SSH 已配对不代表门户已有认证；早期门户返回 401、临时码未显示 | 后续在授权且实际取得门户临时码后完成认证，以当前 Windows 用户 DPAPI 保存专用凭据。早期失败按历史保留，不再当作最新永久阻断。 |
| 2026-10-23 | 门户证书发生同公钥续签 | 仅在原 SSH 身份、旧证书、公钥、签发者、目标名称和有效期连续性通过时更新叶证书记录；不接受不同公钥。 |
| 2026-10-23 | 首次闭合可见控制与采集证据 | 已查看真实 Start 菜单和稻视界，验证取景框与快门；1.0.0.22 的非叶片新拍、裁剪、上传与结果哈希绑定。真实叶片和复杂光照未完成。 |
| 2026-10-24 | 低功耗、不可解码短流和启动请求超时 | 未将 HTTP 200 或启动接受写成画面、相机和输入通过；旧成功与新失败按时间分开。受控输入均使用具名限时保护，结束核对恢复。 |
| 2026-10-25 | 模拟手越出追踪范围后，旧点按诊断仍可能误导 | `pose/status` 返回可见性，越界 `tap` 拒绝发送；实验会话可显式解除模拟追踪范围限制，效果仍以实际画面检查。 |
| 2026-10-25 | 新建 Windows 工具 0.1.0 | 共用后端已有真实视频、范围、菜单、历史、原图、Home、断流拒绝输入和恢复记录。Windows 窗口编译与离线渲染通过，完整鼠标窗口流程未完成。 |
| 2026-10-25 | 重新核查微软现成工具 | 确认官方独立预览包 3.0.24.0 的来源和签名/哈希，提供下载核查与选择性安装脚本。官方 GUI 真机对照仍待进行，不能用包可取得代替验收。 |
| 2026-10-25 | 分阶段整理通用资料 | 单列第二阶段分支、门户和依赖手册、官方对照测试计划；消除恢复保护构建器中原机 Visual Studio 版本路径依赖。新电脑与官方 GUI 的实际兼容性保留待验收。 |
