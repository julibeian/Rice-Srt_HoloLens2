## 0. 一页结论

1. **USB 不是瓶颈**：链路 705 Mbps，到设备 HTTP 往返中位 4.8 ms，视频只占 0.6%。
2. **延迟主要来自视频管线和交互模型**，不是带宽：
   - 设备侧编码/发送缓冲；
   - 工具把画面**上限锁在 12 fps**，并做了一次 JPEG 重编码、又一次 JPEG 解码；
   - 每帧 2–3 次整图拷贝，全部压在 UI 线程附近；
   - 每次点按要“移准星 → 等新帧 → 确认 → 点按 → 再等新帧”。
3. **“来回低效”是设计问题**：控制消息只有几十到几百字节，谈不上流量；真正贵的是“每个动作等一整帧”。
4. **官方 GUI 不能作为替代**：本环境实测其鼠标/键盘输入不产生设备端可见结果；其“鼠标绝对位置 = 人体朝向”的映射本身也放大了难控。
5. **AR 6DoF 与鼠标的矛盾**只在 world-locked / 视差 / 三维内容上明显；对二维应用窗口，用“2D 坐标 → 射线命中”即可自洽。

## 2. 问题清单（带证据）

| 编号 | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| P1 | 画面被锁在 12 fps | `DeviceSession.cs:122` 的 `-vf fps=12` | 直接造成“一顿一顿”，并放大每次点按的等待 |
| P2 | MJPEG 二次编解码 | 同处 `-f image2pipe -vcodec mjpeg -q:v 3`，UI 再 `Image.FromStream` | 每帧多一次编码+一次解码，增加延迟与 CPU |
| P3 | 每帧 2–3 次整图拷贝 | `DeviceSession.Snapshot()` 复制；`MainForm.SetFrame(new Bitmap(input))` 再复制 | 1280×720×4B ≈ 3.7 MB/帧的 memcpy 与 GC 压力，挤占 UI 线程 |
| P4 | 交互用高清流 | `apps/pc-control/ops/Stream-Video.ps1:9` 固定 `live_high.mp4` | 解码量大、帧更慢；交互并不需要高清 |
| P5 | 每个动作都等新帧 | `DeviceSession.cs:151` 的 `while(FrameSequence<after+count)` | 单次点按往返 1–2 s 的主因 |
| P6 | 校准期做整图像素扫描 | `PointerGeometry.Find` 在点按路径上做 24bpp 拷贝与扫描 | 点按时额外 CPU 峰值与延迟 |
| P7 | 设备睡眠导致断流 | 40 字节无效流（10-28 12:20） | 最明显的“卡死/重新连接” |
| P8 | 证据/日志与控制同路径 | 会话 `events.jsonl`、截图落盘与控制同一进程 | 证据写盘可能阻塞交互 |

## 3. 根因分层

```text
链路层      USB NCM 705 Mbps / 4.8 ms      ← 不是瓶颈（实测）
编码层      设备 H.264 编码、GOP/发送缓冲     ← 单帧延迟的大头（未单独量化）
管线层      12 fps 上限、MJPEG 中转、整图拷贝  ← 可立即优化的部分
交互层      盲点按 + 每步等帧 + 事后校验      ← “低效感”的根因
电源层      不戴即熄屏、断流后需重连          ← 稳定性问题
```

## 7. 与官方 GUI 的对照

- 官方 GUI 的**视频可用**（本环境已看到真实 Start 菜单与稻视界画面），码率量级与我们的 `live_high` 相近；
- 官方 GUI 的**输入不落地**：输入 WebSocket 有字节（最高约 1 亿），但 `Body yaw/pitch` 与画面不变，重启设备、换输入源开关、手势按钮均未改变结论；
- 官方把**鼠标横坐标映射为人体绝对朝向**（实测 655 px ≈ -0.83 rad，中心 ≈ -0.15），这不是“转头”，而是“跳朝向”，所以难控；
- 因此主产品输入路线仍按 T05 的官方 SDK 自制适配器推进，官方 GUI 只保留为对照与画面来源之一。

## 8. AR 6DoF 与鼠标的语义矛盾（摘要）

- AR 视野 = 6DoF 头姿 + 前庭/本体感觉；鼠标只有 2D，通常只映射 yaw/pitch，丢平移；
- 对**二维应用窗口**，选择只需“2D 坐标 → 射线命中”，不需要模拟人头，矛盾很小；
- 对 world-locked、视差、三维放置、gaze 交互，矛盾明显；
- 解法：视角与指针分离；视角用显式增量控件（拖动/方向键/回中）；选择用命中而不是头姿注入；单控制者互斥（已有 300 秒具名保护）。

## 9. 边界

- 不修改微软二进制、系统代理、安全设置、门户账号或配对；
- 设备播放音量保持用户要求的 0% 静音；
- 每次真机输入仍需具名 300 秒保护，结束核对自身流与 `Default(0)`；
- 原始室内画面与设备日志只留本机；
- 本文的“目标值”是待验证目标，不是已达成结果。
