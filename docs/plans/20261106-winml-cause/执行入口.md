# WinML 降速定因与改善

目标：在原 HoloLens 上复现持续动态检测的 WinML 降速，通过可逆对照找出触发条件，实际验证改善。

继续中。已复现模式变化、GPU 时间分配与 WinML 耗时的可逆关系，但不能把跨时段漂移全部归到 GPU 排队或某个系统进程。四轮交替对照的已观测耗时约降低 19.8%，完成检测率约提高 19.1%，独立复算见 `comparison-audit.json`。20:02、20:31 续查未发现原 USB 设备；不能据 16:45 的记录声称当前在线。报告见 `reports/20261106-winml-cause/定因与改善报告.md`。

下一步候选为 `reports/20261106-winml-cause/next-preview64/package-evidence.json`，已构建、未部署，沿用 1.0.0.63 的模型和原生 DLL。连接恢复后先核对当前版本、原身份和 Default(0)，完成 1.0.0.63 长跑；再明确安装诊断候选，运行 `apps/field-app/ops/Run-PreviewLoadControl.ps1 -RunId <新名称>`，在同一会话交替显示/遮罩预览。该试验保持物理 PV 采集、布局和推理，遮罩 120 秒自动恢复；每段必须验证新帧时间戳、像素摘要和固定窗口尺寸，不能以重复帧或停止预览采集取得虚假提速。试验后须恢复关闭诊断入口的正式包并重新核验。

1. 保留未修改 1.0.0.48 的长时间运行基线、同包重启对照；核对真实新帧、原设备和模型。
2. 读取 GPU 时钟/温度接口及错误原值，结合门户热缓解、供电和逐引擎使用率。接口不支持时明确记录，不以热阶段 0 排除底层限频。
3. 固定模型、320 输入和相机，分离张量分配/绑定、Evaluate、输出同步和后处理耗时；测试资源复用。
4. 同一会话交替改变检测间隔、预览负载并恢复，检查降速是否可逆，保留每次原始观察和操作编号。
5. 验证改善的连续相机吞吐、预览和数值正确性、停止/重载、长时间稳定性。根据实测决定生产配置；不把限速、平滑或准确率未测当作性能/准确率提升。
