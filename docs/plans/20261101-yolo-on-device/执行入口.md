# YOLOv8n 眼镜内动态部署

2026-11-01 用户目标：删除眼镜动态通道的 ConvNeXt 分类路径，适配下载的 YOLOv8n 六类病虫害检测模型，并部署到眼镜内。

## 执行步骤

1. 冻结相关源码和旧设备安装状态，核对原设备身份、门户及有效相机/视频状态。
2. 删除应用的 ConvNeXt 动态上传、十类分类/CAM 与对应服务部署接线；旧报告作为历史证据保留，不回退到该路径。
3. 检查眼镜 WinML/ARM64 运行时。适配 YOLO ONNX 的算子版本和运行方式，保留六类映射；转换后与原模型比较真实样本和数值输出。
4. 实现眼镜本地原生推理组件，连续读取原始 PV 新帧，执行 RGB/letterbox、YOLO、NMS 和坐标反映射；仅保留当前任务及最新结果。
5. 改造动态界面，持续展示真实预览与目标框，支持开始/停止、无目标、错误和过期清除；不恢复单次静态拍照加反馈的产品路线。
6. 构建 ARM64 应用，按原身份部署，核对安装版本、实际会话、模型哈希、连续相机帧推理和画面内检测框。正式包仅申请相机权限且 `connect-src 'none'`，在无应用网络权限下实际运行；PC 仅部署/读日志/查看画面，不为证明离线而切断整机网络。
7. 完成停止、资源释放和恢复核对，保存版本/源码/模型/运行证据及适用限制。

## 完成要求

- 新应用动态识别没有 ConvNeXt/CAM/云端动态帧调用或隐式回退。
- 六类 YOLO 权重在 HoloLens 应用包内，原生 ARM64 运行时实际加载并持续推理；不是 PC/云代算。
- 实际相机帧至少 30 个不同新帧连续推理，记录时间戳、时延、失败与模型身份；以真实画面验证预览和框层。
- 无实物叶片时，内置症状样本仅验证同一原生推理与框显示；真实叶片/多光照/准确率保持未验收，不伪造现场阳性。
- 已知稻瘟病/胡麻斑病混淆和默认阈值漏检保留，不把多帧平滑当作准确率修复。
- 根 README 不编辑；既有静音、SSH/门户身份、USB 功耗策略及具名输入恢复约束保持。

进度以同目录 `任务状态.json` 为准。没有完整运行证据前不标记完成。
