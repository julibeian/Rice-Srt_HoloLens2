# HoloLens 设备控制（Windows）

版本：0.3.3，本机预览。属于 **第二阶段：HoloLens 整机操作与管理**，阶段状态仍为进行中。整体范围和能力登记见 [整机实施入口](../docs/milestones/phase-2-hololens-control/README.md)。

在电脑上观看已配对 HoloLens 的真实全息画面，并通过鼠标定位和点按、方向键或右键拖动调整视角。

新电脑先完成 [第一阶段 USB 管理连接](../docs/milestones/phase-1-usb-terminal/manual.md)，再按 [第二阶段通用手册](../docs/milestones/phase-2-ricefield-control/manual.md) 配置门户、SDK、应用和恢复保护。微软 **3.0.24.0** 官方控制软件的获取及对照测试见 [独立测试计划](../docs/milestones/phase-2-ricefield-control/official-3.0.24.0-test.md)。本工具的后端验证不等于官方 GUI 或完整桌面窗口流程已通过。

## 启动

在本机完成配置和构建后，双击桌面的 **稻视界眼镜控制**，或打开 `dist/RiceHoloLensControl.exe`。软件启动后核对配置的 USB 设备、SSH 身份、门户服务器密钥和当前 Windows 用户保存的凭据，随后显示画面。已有认证通过时，无需在窗口中重复输入密码或 PIN。

1. 等待实时画面更新，再点击 **开始控制**。控制会话不强制打开业务应用；可先使用 **开始菜单**，或从 **已安装应用** 中选择入口并点击 **打开所选应用**。首次点按时校准鼠标，校准期间不要点按其他控件。
2. 在视频里单击要操作的位置。软件会移动眼镜准星，从新的画面确认其位置，再发送一次点按。查看画面确认实际页面变化。
3. 右键拖动或点击方向按钮调整视角。调整后首次点按会重新校准；**靠近／退后**改变虚拟观看距离。
4. 点击 **开始菜单**发送 Home 手势。应用列表来自当前设备，启动前再次核对 AUMID 和包版本。启动请求被接受后继续查看实际画面；结果未知时按钮变为 **核对上次启动**，只查询原操作。
5. 点击 **停止控制 · 恢复眼镜**结束控制。关闭窗口也会关闭本次输入流并核对设备恢复结果。

控制显示剩余时间，单次最长 5 分钟；电脑端以单调时钟计算剩余时间，临近到期自动结束，可以再次点击“开始控制”。电脑进程意外退出时，设备端同名保护独立到期恢复正常模式。画面过期、准星未确认、设备身份或认证核对失败时，不发送点按。不要在不清楚前次结果时重复点击。

## 画面与响应

默认 **交互画面** 使用官方 `live_med.mp4`，输出 854×480；**高清画面** 使用 `live_high.mp4`，输出 1280×720。切换清晰度后重新取得首帧并使旧校准失效。**抓取一张高清画面**会临时切到高清、保存 PNG，再等待交互画面恢复；真机约需 7 秒，其间暂停输入并提示进度。已在高清模式时直接保存当前新鲜帧。设备会在启动另一清晰度的视频流时结束旧流，因此采用串行切换，避免互相抢占。`live.mp4` 实际也是高清入口。

视频由后台 FFmpeg 直接输出 BGRA，没有 12 fps 限制或 JPEG 中转。解码器写入固定容量帧池，界面只取得最新帧并双缓冲绘制，慢绘制不积压旧帧。状态栏分别显示来源、清晰度、实际绘制帧率和接收帧龄；帧龄以电脑单调时钟计算，**不等同于设备采集到电脑显示的总延迟**。

鼠标本地准星立即随光标移动；发送选择前，仍需从连续两帧确认眼镜准星。校准改用可见范围内的小步长探测，拒绝不一致映射；定位只扫描目标附近的原始像素。白色文字遮住准星时可在现有命中容差内微调悬停，只有重新确认位置后才发送一次选择。首次校准的基准等待单独保留，普通点按已去掉原来的 900 ms 和八帧等待。日志和截图编码在后台执行。

断流后先读取原设备低功耗状态。只读观看遇到休眠时不注入输入；用户点击 **开始控制 / 尝试唤醒**后，先建立具名 300 秒保护，再尝试 presence 并等待新画面。控制期间每 30 秒发送 presence 保活，视频最多自动重启三次；仍未恢复时明确提示重新连接，不启动或抢占业务应用。不能保证所有关机、锁屏或深度低功耗状态均可远程恢复。

10 月 28 日改前后实测、误识别修正和剩余性能目标见 [延迟修复记录](../docs/milestones/phase-2-hololens-control/latency-20261028.md)。原始设备画面和逐次点击证据保留本机，四类界面的完整通用交互验收仍单独进行。

0.3.2 修复运行中切换显示缩放导致视频超出容器、被窗口裁切的问题。100%／125%／150% 的真实电脑显示缩放下，普通窗口和全屏的本机原始帧绘制与鼠标映射已检查，设备端点按回归仍待补齐。此前 0.3.1 在同场景真实视频的三轮测量中，GUI 及子进程合计 CPU 比改前降低约 48.2%，实际绘制约 20.7 fps；此成绩没有改记到 0.3.2。详见 [显示缩放与 CPU 记录](../docs/milestones/phase-2-hololens-control/latency-20261029-dpi.md)。

0.3.3 修复设备脚本输出结束后仍可能无期限等待的问题。标准输出、错误输出与进程退出共用 45 秒预算，超时只结束本次子进程，不自动重发设备操作；原编号用于核对未知结果。九类本机管道与消息循环检查、新版实际后端 45 秒对照及真实只读查询已通过，视频／输入成绩仍保留原版本归属。详见 [操作等待修复](../docs/milestones/phase-2-hololens-control/operation-deadline-20261029.md)。

## USB 接入时的正常功耗

本机已按用户要求启用 USB 功耗保活：原身份通过核对、且实际路由经过 USB 网卡时，已有后台桥向设备端代理续约。即使系统把 USB 连接报告为电池供电，也会覆盖电池分支的休眠、无人值守休眠和显示超时；原值先保存到设备。关闭桌面窗口不关闭这项连接策略。

电脑持续发送保活，设备端以单调时钟判断 45 秒租约。连接丢失或停用后，仍在运行的设备端代理恢复原设置；用户中途改过的值保留并报告冲突。后台通过推进的确认序号判断代理存活，重启前的旧回执不能被当作当前仍有效。输入控制仍使用独立的 300 秒具名保护，功耗保活不会开启模拟输入或解除锁屏。

```powershell
runtime/powershell/pwsh.exe -NoProfile -File Enable-HoloLensUsbPower.ps1
# 停用后最多约 45 秒恢复原电池休眠设置
runtime/powershell/pwsh.exe -NoProfile -File Enable-HoloLensUsbPower.ps1 -Disable
```

10 月 29 日上午曾恢复设备画面并确认正常功耗，验证了租约到期及最终代理显式退出的原值恢复。12:34–13:56 管理链路曾离线，重连后又读到低功耗；后台确认序号推进不能证明已恢复视频，也不足以认定连续连接期间保活失效。当前重连自动唤醒仍未成功，真实 USB 拔插全流程也待验证。设备已深度休眠时，普通 presence/显示请求未必能唤醒；本次使用过一次受控重启请求恢复，没有添加循环自动重启。详情见 [10 月 29 日续做](../docs/milestones/phase-2-hololens-control/latency-20261029.md) 与 [重连排查](../docs/milestones/phase-2-hololens-control/power-20261029-afternoon.md)。

列表可能包含系统组件和多个同名应用，包身份与版本保留在运行记录中。列表读取失败与空清单分别处理，不能用空列表推断应用已卸载。通用启动与系统设置导航有本机实测起点；跨三应用各五轮、四类点按正确率、中文与三维交互仍待验收。0.3.0 的 150% 普通／全屏与 0.3.1 的 100% 普通／全屏已有设备 trusted 读回；0.3.2 的三种 DPI 本机映射检查通过，完整真机回归仍待验收。

**保存画面**只将本次全息视频帧保存到本机运行目录，可通过 **运行记录** 打开。视频关闭独立 PV 和两路音频，但应用自身显示的相机预览仍会出现在全息画面内。

## 依赖与构建

它依赖完整项目中的 `config.json`、已配对的 USB 桥、专用 PowerShell 7、官方 legacy x86 SDK 控制器、FFmpeg、设备端恢复保护的构建工具和当前 Windows 用户保存的 DPAPI 门户凭据。其他电脑分别完成配置与构建，保留项目目录结构；不把现有 EXE、`runtime.json` 或加密凭据直接复制为独立安装包。

```powershell
runtime/powershell/pwsh.exe -NoProfile -File holographic-control/ops/Build-Control.ps1
runtime/powershell/pwsh.exe -NoProfile -File pc-control/Build.ps1 -DesktopShortcut
runtime/powershell/pwsh.exe -NoProfile -File pc-control/ops/Build-Tests.ps1
```

需要 .NET Framework 4.8 或更新版本，使用系统 C# 编译器构建 Windows Forms 程序，无需安装 Python 或 Node 依赖。`RiceHoloLensControl.exe.config` 与 EXE 一起构建和部署，启用每显示器 DPI 缩放；不能只复制 EXE 丢失配置。构建时从当前 `ffmpeg` 命令解析视频解码器位置，保存在本机生成的 `dist/runtime.json`。界面、解码器和认证子进程之间使用私有管道，不建立网页服务器或开放监听端口。密码、CSRF cookie/token 不进入命令行或桌面程序日志。

`desktop/DeviceSession.cs` 管理身份核对、视频、输入、准星确认与设备恢复；`desktop/PointerGeometry.cs` 处理视频缩放和鼠标坐标；`desktop/MainForm.cs` 为界面。`tests/DeviceSmoke.cs` 是同一后端的显式真机测试入口，与桌面窗口使用同一互斥锁，避免两个本工具会话同时控制设备。

运行记录位于 `.state/sessions/<时间-编号>/`，均保留本机。同一后端已真机验证真实视频、范围切换、功能菜单、历史记录打开、原图切换、开始菜单、断流拒绝输入和停止恢复。0.3.0 已获得真实 Windows 窗口中的选应用、打开、开始控制、普通与全屏点按、停止恢复及清晰度切换证据；旧的“窗口无法激活”只代表早期工具观察。复杂系统窗口、文本输入、拖拽物体、持续拖动和任意应用的全部控件仍未完成验收。真实叶片和复杂光照验收独立保留。
